## 문제 해결 근거

### 왜 이전에 실패했는가?

1. **Legacy MetadataDB + WAL 모드**
   - `modules_legacy.metadata_db`가 WAL 모드를 부적절하게 처리
   - INSERT가 WAL에만 기록되고 main DB로 checkpoint 안 됨
   - WAL 파일 삭제 시 변경사항 소실

2. **실패 감지 불가**
   - `add_document()`가 실패 시 `-1` 반환하지만 상위에서 무시
   - 로그에는 "DB 저장 성공"으로 표시되지만 실제로는 롤백됨
   - 파일은 year 폴더로 이동되어 "처리된 것처럼" 보임

### 왜 지금은 성공하는가?

1. **새 MetadataDB 사용**
   - `app.data.metadata_db`는 스키마 마이그레이션 자동 처리
   - WAL 모드를 일관되게 관리
   - PRAGMA 설정이 통일됨

2. **실패 즉시 감지**
   - `doc_id <= 0`이면 즉시 예외 발생
   - 예외 발생 시 파일 이동 취소
   - 로그에 실제 doc_id가 명시됨

### Journal Mode 변경 고려 (선택사항)

```python
# app/data/metadata_db.py 초기화 시
with self._get_conn() as conn:
    mode = conn.execute("PRAGMA journal_mode=DELETE;").fetchone()[0]
    logger.info(f"SQLite journal_mode set to: {mode}")
```

장점: 단순성, WAL 파일 관리 불필요
단점: 동시성 약간 감소 (이 프로젝트에서는 큰 영향 없음)
