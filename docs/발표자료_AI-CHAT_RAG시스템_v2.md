## 슬라이드 3: AI로 개발한다는 것 (바이브 코딩)

### 바이브 코딩(Vibe Coding)이란?

**"코드를 직접 안 짜고, AI한테 시켜서 만드는 것"**

| 기존 개발 | 바이브 코딩 |
|-----------|-------------|
| 프로그래밍 언어 공부 | AI한테 설명 |
| 코드 직접 작성 | AI가 코드 생성 |
| 에러 직접 디버깅 | AI한테 에러 보여주기 |
| 몇 개월~몇 년 | **몇 주~몇 달** |

### 사용한 도구
- **Claude Code**: AI 코딩 어시스턴트
- **VS Code**: 코드 편집기
- 대화하듯 "이렇게 해줘" → AI가 코드 작성

### 핵심 메시지
> **"개발자가 아니어도, AI를 활용하면 시스템을 만들 수 있다"**

## 슬라이드 4: RAG가 뭔가요? (쉬운 설명)

### RAG = "검색해서 답변하는 AI"

**RAG** = Retrieval-Augmented Generation
= **검색** + **AI 답변 생성**

### 비유로 설명하면...

**일반 ChatGPT**
> 선생님한테 질문 → 선생님 머릿속 지식으로 답변
> (학습한 것만 알고, 우리 회사 문서는 모름)

**RAG 시스템**
> 선생님한테 질문 → 선생님이 **도서관에서 책 찾아봄** → 책 보고 답변
> (우리 회사 문서를 찾아서 답변!)

### 한 줄 요약
> **"AI가 우리 문서를 찾아보고 답변해주는 시스템"**

---

## 슬라이드 5: RAG 동작 원리 (그림)

### 질문하면 이런 일이 일어납니다

```
[1단계] 사용자 질문
   "광화문 4층 공유기 IP 알려줘"
          ↓
[2단계] 문서 검색
   📚 1,000개 PDF 중에서 관련 문서 찾기
   → "채널A_광화문_IP_현황.pdf" 발견!
          ↓
[3단계] 문서 읽기
   PDF에서 IP 정보 추출
   "내부 IP: 192.168.0.1, 외부 IP: 175.192.226.7..."
          ↓
[4단계] AI가 답변 생성
   "광화문 4층 공유기 IP 정보입니다:
    - 내부 IP: 192.168.0.1
    - 외부 IP: 175.192.226.7
    - 게이트웨이: 192.168.0.254"
          ↓
[5단계] 사용자에게 답변 표시
```

### 소요 시간: **5~10초**
(사람이 찾으면 30분~1시간)

## 슬라이드 6: 핵심 용어 정리

### 알아두면 좋은 용어들 (쉽게!)

| 용어 | 쉬운 설명 | 비유 |
|------|-----------|------|
| **LLM** | 대규모 언어 모델 (Large Language Model) | AI의 "두뇌" |
| **7B / 72B** | 모델 크기 (70억 / 720억 파라미터) | 두뇌 크기 (작음/큼) |
| **벡터** | 문장을 숫자로 바꾼 것 | 문장의 "지문" |
| **임베딩** | 벡터로 변환하는 과정 | 지문 채취 |
| **BM25** | 키워드 검색 방식 | 구글 검색처럼 |
| **토큰** | AI가 읽는 단위 | 단어/글자 조각 |
| **컨텍스트** | AI가 한번에 읽는 양 | 시험지 길이 |

### 예시
> "광화문 공유기 IP" → 벡터로 변환 → 비슷한 문서 찾기

## 슬라이드 7: 왜 LLM 모델이 중요한가?

### 모델 크기 = 답변 품질

| 모델 크기 | 비유 | 답변 품질 |
|-----------|------|-----------|
| **7B** (70억) | 초등학생 | 간단한 질문만 OK |
| **13B** (130억) | 중학생 | 보통 수준 |
| **72B** (720억) | 대학교수 | 복잡한 질문도 OK |

### 실제 차이 (같은 질문)

**7B 모델 답변:**
> "알려드릴 수 있나요?" (되물음...)

**72B 모델 답변:**
> "광화문 4층 공유기 IP입니다:
> - 내부: 192.168.0.1
> - 외부: 175.192.226.7"

### 결론
> **큰 모델 = 똑똑한 답변**
> (대신 좋은 컴퓨터가 필요함)

## 슬라이드 11: 겪은 어려움들

### 어려움 1: PDF 인식 (OCR)
**문제**: 스캔한 PDF는 글자 인식이 안 됨
**해결**: Tesseract OCR 엔진 적용
**배운 점**: 스캔 품질이 좋아야 인식률 높음

### 어려움 2: 검색 정확도
**문제**: "공유기 IP" 검색 → 엉뚱한 문서 나옴
**해결**: 도메인 키워드 사전 추가, 검색 알고리즘 개선
**배운 점**: 우리 업무 용어를 AI에게 가르쳐야 함

### 어려움 3: LLM 성능 한계
**문제**: 7B 모델이 복잡한 질문에 "모르겠어요" 함
**해결**: 프롬프트 개선, 더 큰 모델 필요성 인식
**배운 점**: 모델 크기가 답변 품질에 큰 영향

### 어려움 4: 답변이 이상할 때
**문제**: AI가 프롬프트를 그대로 출력함
**해결**: 답변 검증 로직 추가, 재시도 기능
**배운 점**: AI도 실수함, 검증 필요

> 먼저 왜 이걸 만들었는지 말씀드리겠습니다.
> 저희 기술관리팀에는 기안서, 장비 현황, IP 정보 등 PDF 파일이 천 개가 넘습니다.
> 예를 들어 "광화문 공유기 IP가 뭐였지?" 하면 폴더 뒤져서 파일 하나씩 열어봐야 해요.
> 30분에서 1시간은 기본이고, 담당자가 휴가면 찾기도 힘들죠.
> 그래서 "AI한테 물어보면 바로 답해주면 좋겠다"는 생각에 이 시스템을 만들었습니다.

## 슬라이드 3 (AI로 개발한다는 것)
> "아니 개발자도 아닌데 어떻게 만들었어?" 하실 수 있는데요.
> 요즘은 "바이브 코딩"이라고 해서, AI한테 시켜서 코드를 만드는 방식이 있어요.
> 저도 Claude Code라는 AI 도구를 사용했는데요,
> "이런 기능 추가해줘" 하면 AI가 코드를 짜주고,
> 에러 나면 에러 메시지 보여주면 AI가 고쳐줍니다.
> 핵심은, 개발자가 아니어도 AI를 활용하면 시스템을 만들 수 있다는 겁니다.

## 슬라이드 4 (RAG가 뭔가요?)
> 그럼 RAG가 뭔지 쉽게 설명드릴게요.
> RAG는 "검색해서 답변하는 AI"입니다.
> 일반 ChatGPT는 학습한 것만 알고, 우리 회사 문서는 몰라요.
> 하지만 RAG 시스템은 질문하면 우리 문서를 먼저 찾아보고, 그걸 바탕으로 답변해요.
> 마치 선생님이 도서관에서 책 찾아보고 답변해주는 것처럼요.

## 슬라이드 5 (동작 원리)
> 실제로 질문하면 이런 과정을 거칩니다.
> "광화문 공유기 IP 알려줘" 하면,
> 먼저 1,000개 PDF 중에서 관련 문서를 찾고,
> 그 문서에서 IP 정보를 추출하고,
> AI가 정리해서 답변해줍니다.
> 이게 다 5~10초 안에 끝나요. 사람이 하면 30분 걸리는 걸요.

## 슬라이드 6 (용어 정리)
> 몇 가지 용어를 간단히 설명드릴게요.
> LLM은 AI의 두뇌라고 생각하시면 돼요.
> 7B, 72B 이런 건 두뇌 크기예요. 숫자가 클수록 똑똑해요.
> 벡터는 문장을 숫자로 바꾼 거고, 이걸로 비슷한 문서를 찾습니다.

## 슬라이드 7 (LLM 중요성)
> LLM 모델이 왜 중요하냐면요,
> 7B 모델, 그러니까 작은 모델한테 "광화문 IP 알려줘" 하면 "알려드릴 수 있나요?" 이렇게 되물어요.
> 근데 72B, 큰 모델은 정확하게 IP 주소를 알려줍니다.
> 그래서 좋은 모델이 필요하고, 좋은 모델을 돌리려면 좋은 컴퓨터가 필요해요.

## 슬라이드 8 (개발 기간)
> 개발 기간은 약 3개월 정도 걸렸어요.
> 첫 주는 RAG 개념 공부하고, 2~3주차에 기본 기능 만들고,
> 그 다음엔 PDF 인식, 웹 화면, 버그 수정 이렇게 진행했습니다.
> 매일 1~2시간씩 Claude한테 "이거 해줘" 하면서 만들었어요.

## 슬라이드 9 (준비 과정)
> 준비는 먼저 PDF 문서들을 정리하고,
> Python이랑 필요한 프로그램 설치하고,
> VS Code랑 Claude Code 세팅했습니다.
> RAG 개념은 유튜브랑 블로그로 공부했고, 모르면 Claude한테 물어봤어요.

## 슬라이드 10 (발전 과정)
> 처음엔 진짜 단순했는데요, 키워드 검색만 됐어요.
> 그 다음 PDF 스캔 문서도 인식하게 OCR 추가하고,
> 검색 정확도 높이려고 하이브리드 검색 적용하고,
> 웹 화면 만들고, 성능 최적화하고... 이렇게 계속 발전했습니다.

## 슬라이드 11 (어려움)
> 어려웠던 점도 있었어요.
> 스캔한 PDF는 글자 인식이 잘 안 돼서 OCR 엔진 적용해야 했고,
> "공유기 IP" 검색하면 엉뚱한 문서 나와서 검색 알고리즘 개선했고,
> 7B 모델이 복잡한 질문엔 "모르겠어요" 해서 더 큰 모델이 필요하다는 걸 알았습니다.

## 슬라이드 12 (장비 비교)
> 그래서 장비를 업그레이드하기로 했습니다.
> 기존엔 일반 PC에 7B 모델이었는데,
> 새로 들어오는 워크스테이션은 H100 GPU에 72B 모델을 돌릴 수 있어요.
> 모델이 10배 커지면 답변 품질도 확 올라갑니다.

## 슬라이드 13 (품질 비교)
> 실제로 같은 질문에 어떻게 다른지 보여드릴게요.
> 7B 모델은 "알려드릴 수 있나요?" 이렇게 되물었는데,
> 72B 모델은 IP 주소, 게이트웨이, DNS까지 정확하게 답변합니다.
> 출처 문서도 같이 보여줘요.

## 슬라이드 14 (성능 요약)
> 수치로 보면요, 답변 정확도가 60%에서 95%로 올라가고,
> 응답 속도도 5배 빨라지고, 처리 가능한 문서 길이도 8배 늘어납니다.
> 체감으로는 "좀 바보 같던 AI"가 "진짜 비서 같은 AI"로 바뀝니다.

## 슬라이드 15 (접속 방법)
> 시스템 접속은 간단해요. 브라우저 열고 주소 입력하면 됩니다.
> 질문 입력창에 질문하면 답변이 나오고, 참고 문서도 보여줍니다.

## 슬라이드 16 (동작 과정)
> 질문하면 내부적으로 이런 과정이 일어납니다.
> 질문 분석하고, 문서 검색하고, 내용 읽고, AI가 답변 생성하고.
> 이게 다 5~10초 안에 끝납니다.
