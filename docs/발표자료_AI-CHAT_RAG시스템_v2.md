## 슬라이드 2: 이런 경험 없으세요?

### 다들 한 번쯤 겪어봤을 상황

**"어... 광화문 공유기 IP가 뭐였더라?"**

1. 폴더 열어봄 → 파일이 너무 많음
2. 파일명 검색 → 안 나옴
3. 하나씩 열어봄 → 30분 경과...
4. 담당자한테 물어봄 → 휴가중
5. 결국 1시간 후 → 겨우 찾음

### 그래서 생각했습니다

> **"이거 AI한테 물어보면 바로 알려주면 안 되나?"**

## 슬라이드 3: 그래서 만들었습니다

### 이제 이렇게 됩니다

**나:** "광화문 4층 공유기 IP 뭐야?"

**AI:** "광화문 4층 공유기 IP 정보입니다:
- 내부 IP: 192.168.0.1
- 외부 IP: 175.192.226.7
- 게이트웨이: 192.168.0.254"

### 소요 시간: 5초

> 1시간 → 5초
> **720배 빨라짐**

## 슬라이드 4: 잠깐, 저 개발자 아닌데요?

### 여기서 핵심 포인트

**"이거 개발자 아니면 못 만드는 거 아니에요?"**

정답: **아니요, 저도 개발자 아닙니다.**

### 비밀은 "바이브 코딩"

**바이브 코딩(Vibe Coding)** = AI한테 시켜서 코드 만들기

쉽게 말하면:
- 나: "로그인 기능 만들어줘"
- AI: (코드 작성)
- 나: "에러나는데?"
- AI: (수정)
- 나: "오 됐다 고마워"

**코드 한 줄 안 쳐도 시스템이 만들어짐**

## 슬라이드 6: RAG를 3초만에 이해하기

### RAG = 검색 + AI

**"AI가 먼저 검색하고, 그 결과 보고 답변하는 것"**

### 비유로 완벽 이해

**일반 ChatGPT** (외운 것만 앎)
> 시험볼 때 머릿속으로만 푸는 것
> → 외운 것만 알고, 새로운 건 모름

**RAG** (찾아보고 답변)
> 시험볼 때 책 펴놓고 푸는 것
> → 모르면 책에서 찾아서 답변

### 핵심
> **ChatGPT는 우리 회사 문서 모름**
> **RAG는 우리 문서 찾아보고 답함**

---

## 슬라이드 7: RAG 동작 원리 (더 쉽게)

### 네이버 검색이랑 비슷해요

**네이버 검색:**
1. 검색어 입력 → 2. 웹페이지 찾음 → 3. 결과 보여줌

**RAG 시스템:**
1. 질문 입력 → 2. 문서 찾음 → 3. **AI가 읽고 정리해서** 답변

### 차이점

| 네이버 | RAG |
|--------|-----|
| 링크 보여줌 | **답변** 해줌 |
| 직접 클릭해서 읽어야 함 | AI가 읽고 정리해줌 |
| 어디 있는지 알려줌 | **뭐라고 써있는지** 알려줌 |

### 한 줄 요약
> **"구글/네이버 = 어디있는지 알려줌"**
> **"RAG = 내용이 뭔지 알려줌"**

---

## 슬라이드 8: 용어 정리 (이것만 알면 됨)

### 어려운 용어, 쉽게 설명

| 용어 | 이게 뭐냐면 |
|------|------------|
| **LLM** | AI 두뇌 (ChatGPT 같은 것) |
| **7B, 72B** | 두뇌 크기. 숫자 클수록 똑똑 |
| **토큰** | AI가 읽는 단위. 대충 글자 1개 = 토큰 1개 |
| **벡터** | 문장을 숫자로 바꾼 것 (검색할 때 씀) |
| **OCR** | 이미지에서 글자 읽는 기술 (스캔 문서용) |
| **프롬프트** | AI한테 하는 질문/명령 |

### 몰라도 되는 것
- 임베딩, 코사인 유사도, 트랜스포머, 어텐션...
- **→ 그냥 몰라도 됩니다**

---

## 슬라이드 9: 왜 큰 모델이 좋은가?

### 모델 크기 = 두뇌 크기

| 모델 | 비유 | 수준 |
|------|------|------|
| 7B (70억) | 초등학생 | "뭐라고요?" |
| 13B (130억) | 중학생 | "음... 아마도..." |
| 72B (720억) | 대학교수 | "정확히 말씀드리면..." |

### 실제 차이 (같은 질문)

**"광화문 공유기 IP 알려줘"**

**7B 답변:**
> "알려드릴 수 있나요?"
> (어... 그래서 뭔데?)

**72B 답변:**
> "광화문 4층 공유기 IP입니다:
> - 내부: 192.168.0.1
> - 외부: 175.192.226.7
> - 게이트웨이: 192.168.0.254
> 출처: 채널A_광화문_IP현황.pdf"

### 결론
> **큰 모델 = 확실한 답변**
> **작은 모델 = 애매한 답변**

## 슬라이드 11: 어떻게 시작했나

### Step 1: 유튜브로 공부

"RAG 만들기" 검색 → 영상 3~4개 봄
→ "아 대충 이런 거구나" 감 잡음

### Step 2: Claude한테 물어봄

"RAG 시스템 만들고 싶은데 뭐부터 해야 해?"
→ AI가 순서대로 알려줌

### Step 3: 시키는 대로 함

"Python 설치해" → 함
"이 코드 실행해" → 함
"에러나면 복붙해서 보여줘" → 함

### 진짜 이게 전부입니다

> **어렵게 생각할 것 없음**
> **AI가 시키는 대로 하면 됨**

## 슬라이드 12: 겪은 어려움들

### 어려움 1: PDF가 안 읽힘

**문제:** 스캔한 문서는 이미지라서 텍스트 추출 안 됨

**해결:** OCR(글자 인식) 기술 적용
→ 이것도 Claude한테 "스캔 PDF 읽게 해줘" 하니까 알려줌

### 어려움 2: 검색이 이상함

**문제:** "공유기 IP" 검색하면 엉뚱한 문서 나옴

**해결:** 우리 업무 용어 사전 추가
→ "공유기 = 라우터 = 네트워크 장비" 이런 식으로

### 어려움 3: AI가 바보같을 때

**문제:** "알려드릴 수 있나요?" 이러면서 답을 안 함

**해결:** 더 큰 모델 필요 → H100 워크스테이션 도입 결정

## 슬라이드 14: 왜 장비를 바꾸나?

### 현재 문제

**7B 모델 (현재)**
- 간단한 질문 → OK
- 복잡한 질문 → "모르겠어요"
- 긴 문서 → 처리 불가

**필요한 것: 더 큰 모델 (72B)**
- 근데 72B는 일반 PC에서 안 돌아감
- GPU(그래픽카드)가 필요함

### 해결책

**H100 워크스테이션 도입**
= AI 전용 슈퍼컴퓨터

### 핵심 변화
> **모델 크기 10배 ↑ = 답변 품질 대폭 ↑**

> 저도 개발자 아닙니다. 코딩 1도 몰라요.
>
> 비밀은 "바이브 코딩"이라는 건데요, 쉽게 말하면 AI한테 시켜서 코드 만드는 겁니다.
>
> "이거 만들어줘" 하면 AI가 코드 짜주고, 에러나면 보여주면 AI가 고쳐주고.
> 코드 한 줄 안 쳐도 시스템이 만들어집니다.

## 슬라이드 5 (바이브 코딩 예시)
> 실제로 제가 한 대화를 보여드리면요,
>
> 저: "PDF에서 텍스트 뽑는 기능 만들어줘"
> AI: "알겠습니다" 하고 코드 작성
> 저: "에러나는데?"
> AI: "아, 한글 문제네요. 수정할게요"
> 저: "오 된다!"
>
> 진짜 이게 전부입니다. 한국어로 설명하면 AI가 알아서 해요.

## 슬라이드 6 (RAG 3초 이해)
> 그럼 RAG가 뭔지 진짜 쉽게 설명드릴게요.
>
> RAG는 "검색 + AI"입니다.
>
> 일반 ChatGPT는 외운 것만 알아요. 시험 볼 때 머릿속으로만 푸는 거죠. 우리 회사 문서는 몰라요.
>
> RAG는 책 펴놓고 시험 보는 거예요. 모르면 책에서 찾아서 답변해요.
>
> 그래서 RAG는 우리 회사 문서를 찾아보고 답변할 수 있는 거죠.

## 슬라이드 7 (네이버 검색이랑 비교)
> 네이버 검색이랑 뭐가 다르냐면요,
>
> 네이버는 "어디 있는지" 알려줘요. 링크 클릭해서 직접 읽어야 해요.
>
> RAG는 "내용이 뭔지" 알려줘요. AI가 읽고 정리해서 답변해줘요.
>
> 구글/네이버 = 어디있는지, RAG = 뭐라고 써있는지. 이 차이입니다.

## 슬라이드 8 (용어 정리)
> 어려운 용어 몇 개만 정리하면요,
>
> LLM은 AI 두뇌예요. ChatGPT 같은 거.
> 7B, 72B는 두뇌 크기인데, 숫자 클수록 똑똑해요.
>
> 나머지 어려운 용어들, 임베딩 코사인 뭐시기... 그냥 몰라도 됩니다.

## 슬라이드 9 (왜 큰 모델?)
> 왜 큰 모델이 좋냐면요,
>
> 7B, 작은 모델한테 "광화문 IP 알려줘" 하면 "알려드릴 수 있나요?" 이래요. 어... 그래서 뭔데?
>
> 72B, 큰 모델은 IP 주소 정확하게 알려줍니다. 출처까지요.
>
> 큰 모델 = 확실한 답변, 작은 모델 = 애매한 답변. 그래서 큰 모델이 필요해요.

## 슬라이드 10 (개발 기간)
> 개발은 약 3개월 걸렸어요. 퇴근 후 1~2시간씩.
>
> 첫 주는 RAG가 뭔지 유튜브로 공부하고, 그 다음엔 Claude한테 물어보면서 만들었습니다.
>
> 모르면 AI한테 물어보고, 에러나면 AI한테 보여주고. 이거 반복이에요.

## 슬라이드 11 (어떻게 시작?)
> 어떻게 시작했냐면요,
>
> 유튜브에 "RAG 만들기" 검색해서 영상 몇 개 봤어요. 대충 감 잡고.
>
> 그 다음 Claude한테 "RAG 만들고 싶은데 뭐부터 해?" 물어봤어요. AI가 순서대로 알려줘요.
>
> 그 다음엔 시키는 대로 했어요. 어렵게 생각할 것 없습니다.

## 슬라이드 12 (어려움들)
> 물론 어려움도 있었어요.
>
> 스캔한 PDF는 이미지라서 글자 인식이 안 됐는데, Claude한테 "스캔 PDF 읽게 해줘" 하니까 OCR이라는 걸 알려줬어요.
>
> 검색이 이상할 때도 있었는데, 우리 업무 용어를 AI한테 알려주니까 나아졌어요.
>
> 근데 AI가 자꾸 "알려드릴 수 있나요?" 이러면서 답을 제대로 안 해서... 더 큰 모델이 필요하다는 걸 알았습니다.
